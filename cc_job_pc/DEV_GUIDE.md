# 开发环境优化说明

## 热更新优化配置

### 主要改进

1. **增加聚合时间**: `aggregateTimeout: 1000ms` - 在1秒内的多次文件变更会被聚合为一次更新
2. **增加HMR超时**: `timeout: 10000ms` - 给热更新更多时间完成
3. **监听间隔优化**: `interval: 1500ms` - 减少文件监听的频率
4. **忽略不必要文件**: 排除 `node_modules`、`.git`、`.vscode` 等目录

### 开发脚本

- `npm run dev` - 标准开发模式
- `npm run dev:quiet` - 安静模式（减少日志输出）
- `npm run dev:debug` - 调试模式（详细日志）

### 环境变量配置

在 `.env.development` 中可以调整以下配置：

- `VITE_HMR_TIMEOUT` - 热更新超时时间
- `VITE_LOG_LEVEL` - 日志级别

### 减少热更新频率的最佳实践

1. **批量修改**: 尽量一次性完成相关的代码修改，而不是逐行修改
2. **使用代码片段**: 对于重复的代码模式，使用IDE的代码片段功能
3. **暂停自动保存**: 在进行大量修改时，可以暂时关闭IDE的自动保存功能
4. **分离开发和调试**: 对于纯调试用的console.log等，可以使用条件编译

### 性能监控

在浏览器开发者工具的Network面板中，可以观察HMR请求的频率：

- 正常情况下，修改文件后应该只有1-2个HMR请求
- 如果看到频繁的HMR请求，说明配置可能需要进一步调整

### 故障排除

如果热更新仍然过于频繁：

1. 检查是否有文件监听工具冲突（如某些IDE插件）
2. 确认项目文件没有在云同步目录中（如OneDrive、Dropbox）
3. 临时禁用杀毒软件的实时保护功能测试
4. 使用 `npm run clean` 清理缓存后重新启动

### 临时禁用热更新

如果需要临时禁用热更新，可以在 `vite.config.ts` 中设置：

```typescript
server: {
  hmr: false;
}
```

或使用环境变量：

```bash
VITE_HMR=false npm run dev
```
