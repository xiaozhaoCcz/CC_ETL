# 20 - 常见问题和解决方案

本章汇总了Netty开发中的常见问题和解决方案，帮助你快速排查和解决问题。

## 1. 内存泄漏问题

### 1.1 问题：ByteBuf没有释放

**现象：**
```
LEAK: ByteBuf.release() was not called before it's garbage-collected.
```

**原因：**
- 忘记调用`release()`
- 异常导致`release()`没有执行

**解决方案：**

```java
// ❌ 错误：忘记释放
public void bad(ChannelHandlerContext ctx, ByteBuf msg) {
    String str = msg.toString(CharsetUtil.UTF_8);
    // 忘记 msg.release()
}

// ✅ 方案1：手动释放
public void good1(ChannelHandlerContext ctx, ByteBuf msg) {
    try {
        String str = msg.toString(CharsetUtil.UTF_8);
        // 处理逻辑
    } finally {
        msg.release();  // 确保释放
    }
}

// ✅ 方案2：使用SimpleChannelInboundHandler（推荐）
public class GoodHandler extends SimpleChannelInboundHandler<ByteBuf> {
    @Override
    protected void channelRead0(ChannelHandlerContext ctx, ByteBuf msg) {
        // 自动释放，不需要手动管理
        String str = msg.toString(CharsetUtil.UTF_8);
    }
}

// ✅ 方案3：传递给下一个Handler
public void good3(ChannelHandlerContext ctx, ByteBuf msg) {
    // 不调用release()，让下一个Handler处理
    ctx.fireChannelRead(msg);
}
```

### 1.2 问题：重复释放

**现象：**
```
IllegalReferenceCountException: refCnt: 0, decrement: 1
```

**原因：**
- 多次调用`release()`
- `write()`后又调用`release()`

**解决方案：**

```java
// ❌ 错误：重复释放
public void bad(ChannelHandlerContext ctx, ByteBuf msg) {
    ctx.write(msg);    // write会释放
    msg.release();     // 重复释放！
}

// ✅ 正确：write后不要release
public void good(ChannelHandlerContext ctx, ByteBuf msg) {
    ctx.write(msg);    // write会自动释放
    // 不要再调用 msg.release()
}
```

## 2. 粘包/半包问题

### 2.1 问题：消息边界混乱

**现象：**
```
发送: "Hello", "World"
接收: "HelloWor", "ld"
```

**解决方案：**

```java
// 方案1：固定长度
pipeline.addLast(new FixedLengthFrameDecoder(10));

pipeline.addLast(new LengthFieldBasedFrameDecoder(1024, 0, 4, 0, 4));

```

## 3. 连接问题

### 3.1 问题：连接建立失败

**现象：**
```
ConnectException: Connection refused
```

**排查步骤：**

```java
/**
 * 连接问题排查
 */
public class ConnectionTroubleshooting {
    
    public static void diagnose(String host, int port) {
        System.out.println("=== 连接诊断 ===");
        
        // 1. 检查网络连通性
        try {
            InetAddress address = InetAddress.getByName(host);
            boolean reachable = address.isReachable(5000);
            System.out.println("网络连通: " + reachable);
        } catch (IOException e) {
            System.err.println("无法解析主机: " + host);
        }
        
        // 2. 检查端口是否开放
        try (Socket socket = new Socket()) {
            socket.connect(new InetSocketAddress(host, port), 5000);
            System.out.println("端口开放: true");
        } catch (IOException e) {
            System.err.println("端口未开放: " + port);
        }
        
        // 3. 检查防火墙
        System.out.println("请检查防火墙设置");
    }
}
```

**解决方案：**

```java
// 设置连接超时
Bootstrap b = new Bootstrap();
b.option(ChannelOption.CONNECT_TIMEOUT_MILLIS, 5000);  // 5秒超时

// 添加连接监听
b.connect(host, port).addListener((ChannelFuture future) -> {
    if (future.isSuccess()) {
        System.out.println("连接成功");
    } else {
        System.err.println("连接失败: " + future.cause());
        // 重试逻辑
        scheduleReconnect();
    }
});
```

### 3.2 问题：连接断开

**现象：**
```
IOException: Connection reset by peer
```

**解决方案：**

```java
/**
 * 自动重连
 */
public class AutoReconnect {
    
    private Bootstrap bootstrap;
    private String host;
    private int port;
    private volatile Channel channel;
    
    public void connect() {
        bootstrap.connect(host, port).addListener((ChannelFuture future) -> {
            if (future.isSuccess()) {
                channel = future.channel();
                System.out.println("连接成功");
                
                // 监听断开事件
                channel.closeFuture().addListener((ChannelFuture closeFuture) -> {
                    System.out.println("连接断开，5秒后重连");
                    scheduleReconnect(5);
                });
            } else {
                System.err.println("连接失败，10秒后重试");
                scheduleReconnect(10);
            }
        });
    }
    
    private void scheduleReconnect(int delaySeconds) {
        bootstrap.config().group().schedule(() -> {
            System.out.println("尝试重连...");
            connect();
        }, delaySeconds, TimeUnit.SECONDS);
    }
}
```

### 3.3 问题：连接泄漏

**现象：**
- 连接数不断增长
- 最终导致OOM或连接数耗尽

**解决方案：**

```java
/**
 * 连接池管理
 */
public class ConnectionPool {
    
    private final Queue<Channel> pool = new ConcurrentLinkedQueue<>();
    private final int maxConnections = 100;
    private final AtomicInteger activeCount = new AtomicInteger(0);
    
    public Channel acquire() throws Exception {
        Channel channel = pool.poll();
        
        if (channel != null && channel.isActive()) {
            return channel;
        }
        
        // 检查连接数限制
        if (activeCount.get() >= maxConnections) {
            throw new IllegalStateException("连接池已满");
        }
        
        // 创建新连接
        channel = createChannel();
        activeCount.incrementAndGet();
        
        return channel;
    }
    
    public void release(Channel channel) {
        if (channel != null && channel.isActive()) {
            pool.offer(channel);
        } else {
            activeCount.decrementAndGet();
        }
    }
    
    private Channel createChannel() throws Exception {
        Bootstrap b = new Bootstrap();
        // 配置...
        return b.connect().sync().channel();
    }
}
```

## 4. 性能问题

### 4.1 问题：延迟高

**排查：**

```java
/**
 * 延迟测量
 */
public class LatencyMeasure extends ChannelDuplexHandler {
    
    private final Map<Long, Long> requestTimes = new ConcurrentHashMap<>();
    private final AtomicLong idGenerator = new AtomicLong(0);
    
    @Override
    public void write(ChannelHandlerContext ctx, Object msg, ChannelPromise promise) {
        long id = idGenerator.incrementAndGet();
        requestTimes.put(id, System.nanoTime());
        // 将ID添加到消息中
        super.write(ctx, msg, promise);
    }
    
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        // 从响应中提取ID
        long id = extractId(msg);
        Long startTime = requestTimes.remove(id);
        
        if (startTime != null) {
            long latency = (System.nanoTime() - startTime) / 1_000_000;  // ms
            System.out.println("延迟: " + latency + " ms");
            
            if (latency > 100) {
                System.err.println("警告: 延迟过高!");
            }
        }
        
        super.channelRead(ctx, msg);
    }
    
    private long extractId(Object msg) {
        // 从消息中提取ID
        return 0;
    }
}
```

**解决方案：**

```java
// 1. 启用TCP_NODELAY（禁用Nagle算法）
bootstrap.option(ChannelOption.TCP_NODELAY, true);

// 2. 减少编解码次数
pipeline.addLast(new EfficientCodec());  // 合并编解码

// 3. 避免阻塞EventLoop
// 见"性能调优"章节
```

### 4.2 问题：吞吐量低

**排查：**

```java
/**
 * 吞吐量监控
 */
public class ThroughputMonitor extends ChannelInboundHandlerAdapter {
    
    private final AtomicLong bytesRead = new AtomicLong(0);
    private long lastTime = System.currentTimeMillis();
    
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        if (msg instanceof ByteBuf) {
            long bytes = ((ByteBuf) msg).readableBytes();
            bytesRead.addAndGet(bytes);
        }
        
        // 每秒统计一次
        long now = System.currentTimeMillis();
        if (now - lastTime >= 1000) {
            long throughput = bytesRead.get() / 1024 / 1024;  // MB/s
            System.out.println("吞吐量: " + throughput + " MB/s");
            
            bytesRead.set(0);
            lastTime = now;
        }
        
        ctx.fireChannelRead(msg);
    }
}
```

**解决方案：**

```java
// 1. 增加Worker线程数
int cpuCount = Runtime.getRuntime().availableProcessors();
EventLoopGroup workerGroup = new NioEventLoopGroup(cpuCount * 2);

// 2. 使用批量操作
ctx.write(msg1);
ctx.write(msg2);
ctx.write(msg3);
ctx.flush();  // 批量flush

// 3. 调整缓冲区大小
bootstrap
    .option(ChannelOption.SO_RCVBUF, 128 * 1024)
    .option(ChannelOption.SO_SNDBUF, 128 * 1024);
```

## 5. 线程问题

### 5.1 问题：EventLoop阻塞

**现象：**
- 响应变慢
- 新连接无法接受

**排查：**

```java
/**
 * EventLoop监控
 */
public class EventLoopMonitor {
    
    public static void monitor(EventLoopGroup group) {
        ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(1);
        
        scheduler.scheduleAtFixedRate(() -> {
            for (EventExecutor executor : group) {
                if (executor instanceof SingleThreadEventExecutor) {
                    SingleThreadEventExecutor eventLoop = 
                        (SingleThreadEventExecutor) executor;
                    
                    int pendingTasks = eventLoop.pendingTasks();
                    if (pendingTasks > 100) {
                        System.err.println("警告: EventLoop任务堆积! 待处理: " + pendingTasks);
                    }
                }
            }
        }, 0, 5, TimeUnit.SECONDS);
    }
}
```

**解决方案：**

```java
// 使用独立线程池处理业务逻辑
EventExecutorGroup businessGroup = new DefaultEventExecutorGroup(16);
pipeline.addLast(businessGroup, new BusinessHandler());
```

## 6. 并发问题

### 6.1 问题：Handler线程安全

**错误示例：**

```java
// ❌ 错误：非线程安全
public class UnsafeHandler extends ChannelInboundHandlerAdapter {
    private int count = 0;  // 多个Channel共享，不安全！
    
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        count++;  // 并发问题！
        System.out.println("Count: " + count);
    }
}
```

**解决方案：**

```java
// ✅ 方案1：不共享Handler
pipeline.addLast(new SafeHandler());  // 每个Channel创建新实例

// ✅ 方案2：使用线程安全的数据结构
@Sharable
public class SafeHandler extends ChannelInboundHandlerAdapter {
    private final AtomicInteger count = new AtomicInteger(0);  // 线程安全
    
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        int current = count.incrementAndGet();
        System.out.println("Count: " + current);
    }
}

// ✅ 方案3：使用Channel属性
public class SafeHandler extends ChannelInboundHandlerAdapter {
    private static final AttributeKey<Integer> COUNT = 
        AttributeKey.valueOf("count");
    
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        // 每个Channel独立的计数器
        Attribute<Integer> attr = ctx.channel().attr(COUNT);
        Integer count = attr.get();
        if (count == null) {
            count = 0;
        }
        attr.set(count + 1);
    }
}
```

## 7. 编解码问题

### 7.1 问题：解码失败

**现象：**
```
DecoderException: ...
```

**调试技巧：**

```java
/**
 * 调试解码器
 */
public class DebugDecoder extends ByteToMessageDecoder {
    
    @Override
    protected void decode(ChannelHandlerContext ctx, ByteBuf in, List<Object> out) {
        System.out.println("=== 解码调试 ===");
        System.out.println("可读字节数: " + in.readableBytes());
        System.out.println("内容: " + ByteBufUtil.hexDump(in));
        
        // 标记读指针
        in.markReaderIndex();
        
        try {
            // 解码逻辑
            if (in.readableBytes() < 4) {
                System.out.println("数据不足，等待更多数据");
                return;
            }
            
            int length = in.readInt();
            System.out.println("长度: " + length);
            
            if (in.readableBytes() < length) {
                in.resetReaderIndex();
                System.out.println("数据不完整，等待更多数据");
                return;
            }
            
            // 读取数据
            byte[] data = new byte[length];
            in.readBytes(data);
            out.add(new String(data, CharsetUtil.UTF_8));
            
        } catch (Exception e) {
            System.err.println("解码失败: " + e.getMessage());
            in.resetReaderIndex();
            throw e;
        }
    }
}
```

## 9. 问题速查表

| 症状 | 可能原因 | 解决方案 |
|------|---------|---------|
| 内存泄漏 | ByteBuf未释放 | 使用SimpleChannelInboundHandler |
| 消息混乱 | 粘包/半包 | 使用解码器 |
| 连接失败 | 端口/防火墙 | 检查网络配置 |
| 延迟高 | Nagle算法 | 启用TCP_NODELAY |
| 吞吐量低 | 线程数少 | 增加Worker线程 |
| EventLoop阻塞 | 业务耗时 | 使用独立线程池 |
| 并发问题 | Handler共享 | 使用@Sharable或不共享 |
| 解码失败 | 数据格式错误 | 添加调试日志 |
