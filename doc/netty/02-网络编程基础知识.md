# 02 - 网络编程基础知识

在深入学习Netty之前，我们需要理解一些网络编程的基础概念。这些知识将帮助你更好地理解Netty的设计理念。

## 1. TCP/IP协议栈

### 1.1 网络分层模型

```
┌─────────────────────┬─────────────────────┐
│    应用层 (HTTP)     │   你的Netty程序      │
├─────────────────────┼─────────────────────┤
│    传输层 (TCP)      │   Socket编程         │
├─────────────────────┼─────────────────────┤
│    网络层 (IP)       │   路由、寻址         │
├─────────────────────┼─────────────────────┤
│  数据链路层 (以太网)  │   硬件、MAC地址      │
└─────────────────────┴─────────────────────┘
```

**Netty主要工作在应用层和传输层**，帮助我们更方便地处理TCP/UDP网络通信。

### 1.2 TCP连接三次握手

```
客户端                                服务器
   │                                    │
   │──────1. SYN (seq=x)──────────────>│  客户端发起连接
   │                                    │
   │<─────2. SYN-ACK (seq=y, ack=x+1)──│  服务器响应
   │                                    │
   │──────3. ACK (ack=y+1)────────────>│  确认连接
   │                                    │
   │          连接建立完成               │
```

**为什么需要三次握手？**
- 确认双方都有发送和接收数据的能力
- 防止已失效的连接请求突然又传到服务器

### 1.3 TCP四次挥手

```
客户端                                服务器
   │                                    │
   │──────1. FIN (seq=x)──────────────>│  客户端请求关闭
   │                                    │
   │<─────2. ACK (ack=x+1)─────────────│  服务器确认
   │                                    │
   │<─────3. FIN (seq=y)───────────────│  服务器请求关闭
   │                                    │
   │──────4. ACK (ack=y+1)────────────>│  客户端确认
   │                                    │
   │          连接关闭完成               │
```

## 2. 五种IO模型

理解IO模型对于理解Netty的高性能至关重要！

### 2.1 阻塞IO（BIO - Blocking IO）

这是最传统的IO模型。

```java
// 阻塞IO示例
public class BlockingIOExample {
    public static void main(String[] args) throws IOException {
        ServerSocket serverSocket = new ServerSocket(8080);
        System.out.println("服务器启动，等待连接...");
        
        // accept()会阻塞，直到有客户端连接
        Socket socket = serverSocket.accept();
        System.out.println("客户端已连接");
        
        InputStream input = socket.getInputStream();
        byte[] buffer = new byte[1024];
        
        // read()会阻塞，直到有数据到达
        int len = input.read(buffer);
        System.out.println("收到数据: " + new String(buffer, 0, len));
    }
}
```

**工作流程：**

```
线程                             内核
 │                                │
 │────── read() 系统调用 ────────>│
 │                                │
 │         等待数据（阻塞）         │  等待网络数据到达
 │                                │
 │<──────── 数据准备好 ───────────│
 │                                │
 │<──────── 复制数据 ─────────────│  将数据从内核复制到用户空间
 │                                │
 │         处理数据               │
```

**特点：**
- ✅ 简单易懂
- ❌ 线程阻塞，资源浪费
- ❌ 一个连接需要一个线程
- ❌ C10K问题（无法处理10000个并发连接）

### 2.2 非阻塞IO（NIO - Non-blocking IO）

```java
// 非阻塞IO示例
public class NonBlockingIOExample {
    public static void main(String[] args) throws IOException {
        ServerSocketChannel serverChannel = ServerSocketChannel.open();
        serverChannel.bind(new InetSocketAddress(8080));
        serverChannel.configureBlocking(false); // 设置为非阻塞
        
        while (true) {
            // accept()立即返回，没有连接时返回null
            SocketChannel clientChannel = serverChannel.accept();
            
            if (clientChannel != null) {
                System.out.println("新客户端连接");
                clientChannel.configureBlocking(false);
                
                ByteBuffer buffer = ByteBuffer.allocate(1024);
                // read()立即返回，没有数据时返回0
                int bytesRead = clientChannel.read(buffer);
                
                if (bytesRead > 0) {
                    System.out.println("收到数据");
                }
            }
            
            // 需要不断轮询，浪费CPU
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
}
```

**工作流程：**

```
线程                             内核
 │                                │
 │────── read() 系统调用 ────────>│
 │                                │
 │<─── EWOULDBLOCK (立即返回) ────│  数据未准备好
 │                                │
 │────── read() 再次调用 ────────>│
 │                                │
 │<─── EWOULDBLOCK ──────────────│  还是没数据
 │                                │
 │────── read() 再次调用 ────────>│
 │                                │
 │<──────── 数据准备好 ───────────│  数据准备好了
 │                                │
 │         处理数据               │
```

**特点：**
- ✅ 不会阻塞
- ❌ 需要不断轮询，浪费CPU
- ❌ 代码复杂

### 2.3 IO多路复用（Netty使用的模型！）

IO多路复用是Netty的核心！它使用select/poll/epoll等机制。

```java
// IO多路复用示例（使用Java NIO的Selector）
public class IOMultiplexingExample {
    public static void main(String[] args) throws IOException {
        Selector selector = Selector.open();
        
        ServerSocketChannel serverChannel = ServerSocketChannel.open();
        serverChannel.bind(new InetSocketAddress(8080));
        serverChannel.configureBlocking(false);
        
        // 注册到选择器，监听ACCEPT事件
        serverChannel.register(selector, SelectionKey.OP_ACCEPT);
        
        System.out.println("服务器启动，等待事件...");
        
        while (true) {
            // select()会阻塞，直到有事件发生
            // 但它可以同时监听多个Channel
            selector.select();
            
            Set<SelectionKey> selectedKeys = selector.selectedKeys();
            Iterator<SelectionKey> iterator = selectedKeys.iterator();
            
            while (iterator.hasNext()) {
                SelectionKey key = iterator.next();
                iterator.remove();
                
                if (key.isAcceptable()) {
                    // 处理连接事件
                    ServerSocketChannel server = (ServerSocketChannel) key.channel();
                    SocketChannel client = server.accept();
                    client.configureBlocking(false);
                    client.register(selector, SelectionKey.OP_READ);
                    System.out.println("新客户端连接：" + client.getRemoteAddress());
                    
                } else if (key.isReadable()) {
                    // 处理读事件
                    SocketChannel client = (SocketChannel) key.channel();
                    ByteBuffer buffer = ByteBuffer.allocate(1024);
                    int len = client.read(buffer);
                    
                    if (len > 0) {
                        buffer.flip();
                        byte[] data = new byte[buffer.remaining()];
                        buffer.get(data);
                        System.out.println("收到数据: " + new String(data));
                    } else if (len == -1) {
                        // 客户端断开连接
                        client.close();
                        key.cancel();
                    }
                }
            }
        }
    }
}
```

**工作流程：**

```
线程                                      内核
 │                                         │
 │────── select([fd1, fd2, fd3]) ────────>│  监听多个文件描述符
 │                                         │
 │         等待（阻塞）                     │  等待任一fd有数据
 │                                         │
 │<──── fd2有数据可读 ────────────────────│
 │                                         │
 │────── read(fd2) ──────────────────────>│
 │                                         │
 │<──────── 返回数据 ─────────────────────│
 │                                         │
 │         处理数据                        │
```

**三种实现方式对比：**

| 方式 | 数据结构 | 时间复杂度 | 最大连接数 | 
|------|---------|-----------|-----------|
| select | 数组 | O(n) | 1024（限制） |
| poll | 链表 | O(n) | 无限制 |
| epoll | 红黑树+链表 | O(1) | 无限制 |

**Netty在Linux下使用epoll，性能最优！**

**特点：**
- ✅ 一个线程可以处理多个连接
- ✅ 不需要轮询
- ✅ 性能优秀
- ❌ 代码相对复杂（但Netty帮我们封装好了！）

### 2.5 异步IO（AIO）

真正的异步IO，操作系统完成IO后通知应用程序。

```java
// 异步IO示例（Java AIO）
public class AsyncIOExample {
    public static void main(String[] args) throws Exception {
        AsynchronousServerSocketChannel serverChannel = 
            AsynchronousServerSocketChannel.open();
        serverChannel.bind(new InetSocketAddress(8080));
        
        System.out.println("服务器启动");
        
        // 异步接受连接
        serverChannel.accept(null, new CompletionHandler<AsynchronousSocketChannel, Void>() {
            @Override
            public void completed(AsynchronousSocketChannel clientChannel, Void attachment) {
                System.out.println("客户端已连接");
                
                // 继续接受下一个连接
                serverChannel.accept(null, this);
                
                // 异步读取数据
                ByteBuffer buffer = ByteBuffer.allocate(1024);
                clientChannel.read(buffer, buffer, new CompletionHandler<Integer, ByteBuffer>() {
                    @Override
                    public void completed(Integer result, ByteBuffer attachment) {
                        attachment.flip();
                        byte[] data = new byte[attachment.remaining()];
                        attachment.get(data);
                        System.out.println("收到数据: " + new String(data));
                    }
                    
                    @Override
                    public void failed(Throwable exc, ByteBuffer attachment) {
                        exc.printStackTrace();
                    }
                });
            }
            
            @Override
            public void failed(Throwable exc, Void attachment) {
                exc.printStackTrace();
            }
        });
        
        // 保持主线程运行
        Thread.sleep(Long.MAX_VALUE);
    }
}
```

**工作流程：**

```
线程                             内核
 │                                │
 │────── aio_read() 系统调用 ───>│
 │                                │
 │<──── 立即返回 ────────────────│  不阻塞
 │                                │
 │    继续做其他事情               │  内核准备数据
 │                                │  内核复制数据
 │                                │
 │<──── 回调通知 ────────────────│  数据已准备好
 │                                │
 │    处理数据                    │
```

**特点：**
- ✅ 真正的异步
- ✅ 不需要轮询
- ❌ Windows下成熟，Linux下不够成熟
- ❌ Netty在5.0版本尝试过AIO，但后来放弃了

**Netty为什么不使用AIO？**
1. Linux下AIO不够成熟
2. epoll已经足够高性能
3. AIO的API更复杂

## 3. Reactor模式

Netty的核心设计模式！

### 3.1 单Reactor单线程

```
                ┌─────────────┐
                │   Reactor   │
                └──────┬──────┘
                       │
        ┌──────────────┼──────────────┐
        │              │              │
   ┌────▼───┐    ┌────▼───┐    ┌────▼───┐
   │Handler1│    │Handler2│    │Handler3│
   └────────┘    └────────┘    └────────┘
```

**示例代码框架：**

```java
class Reactor implements Runnable {
    final Selector selector;
    final ServerSocketChannel serverSocket;
    
    Reactor(int port) throws IOException {
        selector = Selector.open();
        serverSocket = ServerSocketChannel.open();
        serverSocket.bind(new InetSocketAddress(port));
        serverSocket.configureBlocking(false);
        
        // 注册Acceptor
        SelectionKey sk = serverSocket.register(selector, SelectionKey.OP_ACCEPT);
        sk.attach(new Acceptor());
    }
    
    public void run() {
        try {
            while (!Thread.interrupted()) {
                selector.select();
                Set<SelectionKey> selected = selector.selectedKeys();
                Iterator<SelectionKey> it = selected.iterator();
                
                while (it.hasNext()) {
                    dispatch(it.next());
                    it.remove();
                }
            }
        } catch (IOException ex) {
            ex.printStackTrace();
        }
    }
    
    void dispatch(SelectionKey k) {
        Runnable r = (Runnable) (k.attachment());
        if (r != null) {
            r.run();
        }
    }
    
    class Acceptor implements Runnable {
        public void run() {
            try {
                SocketChannel c = serverSocket.accept();
                if (c != null) {
                    new Handler(selector, c);
                }
            } catch (IOException ex) {
                ex.printStackTrace();
            }
        }
    }
}
```

**特点：**
- ✅ 简单
- ❌ 性能有限（单线程）
- ❌ 不适合高并发

### 3.2 单Reactor多线程

```
                ┌─────────────┐
                │   Reactor   │
                └──────┬──────┘
                       │
        ┌──────────────┼──────────────┐
        │              │              │
   ┌────▼───┐    ┌────▼───┐    ┌────▼───┐
   │ 线程池 │    │ 线程池 │    │ 线程池 │
   │Handler1│    │Handler2│    │Handler3│
   └────────┘    └────────┘    └────────┘
```

**特点：**
- ✅ 业务处理并发
- ❌ Reactor仍是单线程，高并发时可能成为瓶颈

### 3.3 主从Reactor多线程（Netty使用！）

```
        ┌──────────────────┐
        │  Main Reactor    │ ← BossGroup
        │  (处理ACCEPT)     │
        └────────┬─────────┘
                 │
        ┌────────▼─────────┐
        │  Sub Reactor-1   │
        ├──────────────────┤
        │  Sub Reactor-2   │ ← WorkerGroup
        ├──────────────────┤
        │  Sub Reactor-3   │
        └──────────────────┘
               │
        ┌──────┴──────┐
        │   线程池     │
        │  (业务处理)  │
        └─────────────┘
```

**Netty实现：**

```java
// Netty的主从Reactor模型
EventLoopGroup bossGroup = new NioEventLoopGroup(1);      // 主Reactor
EventLoopGroup workerGroup = new NioEventLoopGroup();     // 从Reactor

ServerBootstrap b = new ServerBootstrap();
b.group(bossGroup, workerGroup)  // 设置主从Reactor
 .channel(NioServerSocketChannel.class)
 .childHandler(new ChannelInitializer<SocketChannel>() {
     @Override
     protected void initChannel(SocketChannel ch) {
         ch.pipeline().addLast(new YourHandler());
     }
 });
```

**工作流程：**

1. **MainReactor（BossGroup）**：
   - 监听客户端连接
   - accept新连接
   - 将连接分配给SubReactor

2. **SubReactor（WorkerGroup）**：
   - 处理已建立连接的IO操作
   - 一个SubReactor处理多个连接
   - 执行ChannelHandler中的业务逻辑

**特点：**
- ✅ 高性能
- ✅ 职责清晰
- ✅ 适合高并发场景
- ✅ Netty默认采用这种模型

## 4. 零拷贝（Zero-Copy）

### 4.1 传统IO的数据拷贝

```
┌─────────────┐
│  应用程序   │
└──────┬──────┘
       │ 1. read()
┌──────▼──────┐
│  内核缓冲区  │ ← 2. DMA拷贝（磁盘→内核）
└──────┬──────┘
       │ 3. CPU拷贝（内核→用户空间）
┌──────▼──────┐
│  用户缓冲区  │
└──────┬──────┘
       │ 4. write()
┌──────▼──────┐
│  Socket缓冲区│ ← 5. CPU拷贝（用户空间→内核）
└──────┬──────┘
       │ 6. DMA拷贝（内核→网卡）
┌──────▼──────┐
│    网卡     │
└─────────────┘

总共：4次拷贝（2次DMA + 2次CPU）
```

### 4.2 零拷贝技术

使用`sendfile`或`mmap`：

```
┌─────────────┐
│  应用程序   │
└──────┬──────┘
       │ 1. transferTo()
┌──────▼──────┐
│  内核缓冲区  │ ← 2. DMA拷贝（磁盘→内核）
└──────┬──────┘
       │ 3. DMA拷贝（内核→网卡）
┌──────▼──────┐
│    网卡     │
└─────────────┘

总共：2次拷贝（2次DMA，0次CPU）
```

**Netty中的零拷贝：**

1. **CompositeByteBuf**：合并多个ByteBuf，避免拷贝

```java
// 传统方式：需要拷贝
ByteBuf header = ...;
ByteBuf body = ...;
ByteBuf combined = Unpooled.buffer(header.readableBytes() + body.readableBytes());
combined.writeBytes(header);  // 拷贝
combined.writeBytes(body);    // 拷贝

// Netty零拷贝：不需要拷贝
CompositeByteBuf composite = Unpooled.compositeBuffer();
composite.addComponents(true, header, body);  // 只是引用，不拷贝
```

2. **ByteBuf切片**：共享底层数组

```java
ByteBuf buffer = ...;
ByteBuf slice = buffer.slice(0, 5);  // 共享数据，不拷贝
```

3. **FileRegion**：文件传输零拷贝

```java
FileRegion region = new DefaultFileRegion(file, 0, file.length());
ctx.writeAndFlush(region);  // 使用零拷贝发送文件
```

## 6. 对比表格

### IO模型对比

| 模型 | 阻塞性 | 并发能力 | CPU使用 | 复杂度 | Netty是否使用 |
|------|--------|---------|---------|--------|--------------|
| BIO | 阻塞 | 差 | 低 | 低 | ❌ |
| NIO | 非阻塞 | 好 | 高（轮询） | 中 | ❌ |
| IO多路复用 | select阻塞 | 优秀 | 低 | 高 | ✅ |
| 信号驱动IO | 非阻塞 | 好 | 低 | 高 | ❌ |
| AIO | 非阻塞 | 优秀 | 低 | 高 | ❌ |

### Reactor模型对比

| 模型 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| 单Reactor单线程 | 简单 | 性能低 | 连接数少 |
| 单Reactor多线程 | 业务并发 | Reactor瓶颈 | 中等并发 |
| 主从Reactor多线程 | 高性能 | 复杂 | 高并发（Netty） |
