# Cc-ETL 功能增强使用说明

本文介绍「功能增强」中新增功能的详细使用方法，包括 PC 端（JavaFX GUI）操作与开放 API 调用方式。

---

## 一、更多数据源预设（c1）

### 功能说明

在数据源管理与 DataX 同步配置中，除 MySQL、Oracle、PostgreSQL 外，支持 **MongoDB、Elasticsearch、Kafka** 等类型的预设，便于快速填写驱动与连接 URL。

### 使用步骤（PC 端）

1. **数据源管理**  
   - 菜单：**任务 → 数据源管理**，打开数据源列表。  
   - 新增/编辑数据源时，在 **「数据源类型」** 下拉框中选择：  
     `MYSQL`、`ORACLE`、`POSTGRESQL`、`MONGODB`、`ELASTICSEARCH`、`KAFKA`。  
   - 选择 **MONGODB**：驱动与 URL 占位会提示为 MongoDB 格式（如 `mongodb://host:27017/database`）。  
   - 选择 **ELASTICSEARCH**：URL 占位为 `http://host:9200`。  
   - 选择 **KAFKA**：URL 占位为 `localhost:9092 (bootstrap servers)`。  

2. **DataX 同步配置**  
   - 在 **数据源同步** 或 **多数据源同步** 对话框中，Reader/Writer 的 **「数据源类型」** 同样提供上述类型；选择后可按类型自动填充或提示连接信息，再选择具体数据源与表进行同步。

### 说明

- MongoDB/ES/Kafka 的 DataX Reader 配置需与执行器侧已支持的 DataX 插件一致；若执行器未安装对应插件，需自行扩展。  
- 驱动类与 URL 仅为预设提示，实际连接串需根据环境修改。

## 二、数据质量校验（c2）

### 功能说明

在**同步任务成功**后，可自动执行一条校验 SQL（或行数/关键指标对比）。若校验不通过（如结果行数低于预期），该次执行会被置为**失败**，并参与告警与统计。

### 配置方式

- **接口配置**（无独立 GUI 时可通过 Knife4j 或 curl 操作）：  
  - **GET** `/api/v1/jobValidations/byJob/{jobId}`：查询该任务当前校验配置。  
  - **POST** `/api/v1/jobValidations`：保存校验配置。  
    请求体示例：  
    ```json
    {
      "jobId": 123,
      "validationSql": "SELECT COUNT(*) FROM target_table WHERE dt='${date}'",
      "expectedMinRows": 1,
      "jdbcDatasourceId": 2
    }
    ```  
    - `validationSql`：在指定数据源上执行的校验 SQL，通常为 `SELECT`，取第一列数值与 `expectedMinRows` 比较。  
    - `expectedMinRows`：期望的最小行数（或数值），不满足则视为校验失败。  
    - `jdbcDatasourceId`：执行校验 SQL 使用的数据源 ID。  
  - **DELETE** `/api/v1/jobValidations/byJob/{jobId}`：删除该任务的校验配置。  

### 执行逻辑

- 任务**执行成功**后，若存在该任务的校验配置，系统会在对应数据源上执行 `validationSql`。  
- 取查询结果第一列数值，若 **小于** `expectedMinRows`，则将该次执行改为**失败**（并参与失败告警与健康度统计）。  
- 数据库表结构见 `doc/migration_job_validation.sql`，需在目标库执行该迁移脚本。

## 三、DataX 同步预览（c3）

### 功能说明

在正式全量/增量同步前，可只生成 **Reader 前 N 条** 的配置（或 dry-run），用于在界面或脚本中确认数据源与表是否可达、字段是否正确。

### 使用方式

- **API**  
  **POST** `/api/v1/datax/previewReaderJson`  
  请求体示例：  
  ```json
  {
    "dataXParams": { ... },
    "previewLimit": 10
  }
  ```  
  - `dataXParams`：与现有 DataX 任务相同的参数结构（数据源、表、列等）。  
  - `previewLimit`：限制 Reader 只读前 N 条（如 MySQL/PostgreSQL 用 LIMIT，Oracle 用 ROWNUM）。  

- 返回为**仅 Reader 部分**的 JSON 片段，可用于：  
  - 在 GUI 中展示「预览用配置」；  
  - 或交给执行器做 dry-run（若执行器支持预览模式）。  

- **GUI**  
  若数据源同步/多数据源同步对话框中有「预览」或「前 N 条」入口，会调用上述接口并展示生成的 Reader JSON 或预览结果。

## 四、子流程/画布模板复用（d2）

### 功能说明

将当前画布中**选中的节点与连线**保存为「画布模板」，在新建或编辑其他任务组时，可从模板插入，避免重复编排。

### 使用步骤（PC 端）

1. **保存为画布模板**  
   - 在画布中**框选**需要复用的节点（及它们之间的连线）。  
   - 菜单：**查看 → 保存选中为画布模板**。  
   - 在弹出的对话框中输入**模板名称**，确认后保存。模板仅包含当前选中节点及它们之间的连线。  

2. **从画布模板插入**  
   - 打开任意任务组画布。  
   - 菜单：**查看 → 从画布模板插入**。  
   - 在列表中选择一个已保存的模板，确认后会在当前画布上以偏移（如 50,50）插入模板中的节点与连线，可再拖拽调整位置。  

### 说明

- 模板保存在本地（当前实现为内存/本地存储），不随任务组上传到服务端。  
- 适合重复出现的「子流程」片段（如一段固定的清洗 + 写入节点组合）。

## 五、任务组版本与回滚（d1，与增强相关）

### 功能说明

对任务组画布做**版本快照**，支持保存为版本、查看版本列表、按快照回滚到某一版本。

### 使用步骤（PC 端）

1. **保存为版本**  
   - 菜单：**文件 → 版本 → 保存为版本**。  
   - 输入版本名称，系统会将当前画布（节点 + 连线）保存为一条版本记录（randomId 以 `ver_` 开头）。  

2. **版本列表与回滚**  
   - 菜单：**文件 → 版本 → 版本列表与回滚**。  
   - 在列表中选择某一版本，执行「回滚」后，画布会替换为该版本的节点与连线。  

### API（供集成/脚本使用）

- **GET** `/api/v1/jobGroupSnapshots/versions?jobId={jobId}&limit=50`：列出该任务组的版本列表。  
- **POST** `/api/v1/jobGroupSnapshots/saveVersion`：保存为版本（body: `jobId`, `versionName`, `nodesJson`, `edgesJson`）。  
- **GET** `/api/v1/jobGroupSnapshots/{id}`：根据快照 ID 获取节点与连线 JSON，用于回滚或对比。

## 六、审批/人工节点（d3）

### 功能说明

流程执行到「审批节点」时，可在系统中挂起，等待人工在 PC 端或通过 API 审批/拒绝后，再由业务侧决定是否继续执行后续节点。

### 使用方式

- **数据与流程**  
  - 审批节点执行到时，需在业务侧（或扩展的执行器逻辑）创建 `job_approval_pending` 记录，表示有一条待办。  
  - 用户通过 **待办列表** 或 **API** 进行审批/拒绝。  

- **API**  
  - **GET** `/api/v1/approvals/pending?jobId=`：查询待审批列表。  
  - **POST** `/api/v1/approvals/{id}/approve`：审批通过（body 可选 `{"remark":""}`）。  
  - **POST** `/api/v1/approvals/{id}/reject`：审批拒绝。  

- **后续动作**  
  - 审批通过/拒绝后，仅更新待办状态；是否继续执行下游节点、如何触发，由业务或执行器扩展实现（如调用触发接口或回调）。  
  - 表结构见 `doc/migration_job_approval_pending.sql`。

## 七、参数与密钥管理（d4）

### 功能说明

在管理端**统一维护参数/密钥**（如 `db_url`、`password`），任务或 DataX 的 `executorParam` 中使用占位符（如 `${db_url}`），**触发时**由系统自动替换为已配置的值，避免明文写在任务配置中。

### 使用方式

- **API**  
  - **GET** `/api/v1/jobParams`：列出所有参数。  
  - **POST** `/api/v1/jobParams`：新增或更新（body: `paramKey`, `paramValue`, `comment`）。  
  - **DELETE** `/api/v1/jobParams/key/{key}`：按 key 删除。  
  - **POST** `/api/v1/jobParams/resolve`：测试解析。  
    请求体：`{"text": "jdbc:${db_url}"}`  
    返回解析后的字符串（用于确认占位符是否配置正确）。  

- **任务中的使用**  
  - 在任务或任务组的 **执行参数**（executorParam）中填写：`-Ddb_url=${db_url}` 等。  
  - 触发任务时，Admin 会先调用参数解析服务，将 `executorParam` 中的 `${key}` 替换为参数表中对应值，再下发给执行器。  

- **说明**  
  - 参数表结构见 `doc/migration_job_param.sql`。  
  - 密钥类参数建议仅授权给必要人员，或通过环境变量 + 参数 key 的方式间接引用。

## 八、主题与国际化（f1）

### 功能说明

PC 端支持**多主题**（浅色/深色/自动）与**中英文**切换，界面文案与部分控件会随语言与主题变化。

### 使用步骤（PC 端）

1. **主题**  
   - 菜单：**查看 → 主题**，选择 **浅色主题**、**深色主题** 或 **自动**（随系统）。  
   - 切换后主窗口与弹窗样式会立即生效。  

2. **语言**  
   - 菜单：**查看 → 语言**，选择 **中文** 或 **English**。  
   - 语言会持久化（如通过 ConfigManager 的 `locale`）；部分界面需**重启客户端**后完全生效。

## 十、日志检索与归档（f3）

### 功能说明

- **检索**：日志列表支持按 **关键词**（执行结果 handle_msg 模糊匹配）、**时间范围**、**状态**（成功/失败/运行中）、任务/执行器筛选。  
- **归档**：可定期删除「早于 N 天」的日志，保留近期热数据，减少库表压力。

### 使用步骤（PC 端）

1. **日志列表与检索**  
   - 菜单：**任务 → 任务日志**（或从任务组/任务入口进入）。  
   - 在筛选栏中：  
     - **执行器**、**任务状态**、**调度时间**：与原来一致。  
     - **关键词**：输入要匹配的字符串，会按执行结果内容（handle_msg）模糊查询。  
   - 点击「搜索」刷新列表；「重置」清空条件；「清理」按当前筛选条件删除日志（谨慎使用）。  

2. **归档**  
   - 在同一日志列表界面点击 **「归档」** 按钮。  
   - 输入「保留最近 N 天」（如 90），确认后系统会删除早于 N 天的所有日志，并提示本次删除条数。  

### API

- **GET** `/api/v1/jobLogs/page`  
  查询参数：`pageNum`, `pageSize`, `jobId`, `jobGroup`, `logStatus`（1=成功 2=失败 3=运行中）, `filterTime[0]`/`filterTime[1]`, `keyword`。  

- **POST** `/api/v1/jobLogs/archive`  
  请求体：`{ "olderThanDays": 90 }`，返回本次删除条数。

## 十一、快捷键说明与无障碍（f4）

### 功能说明

在帮助中提供**完整快捷键列表**，并简要说明**键盘焦点与可访问性**（Tab 切换、画布内方向键与回车等），便于效率操作与无障碍使用。

### 使用步骤（PC 端）

- 菜单：**帮助 → 快捷键列表**（或 **Ctrl+Shift+?**）。  
- 对话框中按分类列出：  
  - **文件**：Ctrl+N/P/O/S、Ctrl+Shift+S  
  - **编辑**：撤销/重做/剪切/复制/粘贴/删除/全选、查找与 F3/Shift+F3  
  - **视图**：缩放、F11 全屏  
  - **转到**：Ctrl+G、Ctrl+↑/↓ 上/下节点  
  - **布局对齐**：Ctrl+L/C/R/T/M/B  
  - **运行与帮助**：F5、Shift+F5、Ctrl+Shift+?  
- 底部有 **「键盘与可访问性」**：Tab/Shift+Tab 切换焦点、画布内方向键移动节点、回车打开属性；Mac 上 Ctrl 即 Command。

## 十二、开放 API 与告警扩展（e1 / e3）

### 开放 API

- 上述功能中涉及的后端接口，均可在 **Knife4j** 中查看与调试：  
  `http://{admin-host}:8989/xxl-job-admin/doc.html`  
- 汇总说明与 curl 示例见：**doc/开放API.md**（触发、统计、健康度、导出、版本、参数、校验、日志分页与归档、审批等）。

### 告警扩展（SPI）

- 新增告警渠道（如自定义 Webhook、其他 IM）：  
  - 实现接口 `com.cc.job.admin.task.alarm.JobAlarm`，实现 `doAlarm(JobInfo info, JobLog jobLog)`。  
  - 使用 `@Component` 注册，Admin 启动时会自动加载；任务失败时会依次调用所有 JobAlarm 实现（邮件、钉钉、企微、飞书等已有实现可作参考）。  
- 包说明见：`com.cc.job.admin.task.alarm` 包下 `package-info.java`。
